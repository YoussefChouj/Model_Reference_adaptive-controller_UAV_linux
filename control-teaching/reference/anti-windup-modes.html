Anti-Windup Modes

Three selectable anti-windup strategies in ComputePID(), chosen per PID loop via pPID->aw_mode. Default 0 = legacy = original firmware.

The switch

typedef enum {         // robot_types.h
    AW_LEGACY   = 0,   // EMin separation + SumE clamp   (default, unchanged)
    AW_CLAMP    = 1,   // conditional integration on real saturation
    AW_BACKCALC = 2    // back-calculation observer (needs Kt > 0)
} PID_AntiWindup_e;

// per-loop fields appended to PIDTypeDef:
int   aw_mode;   // 0 by default (zero-init)
float Kt;        // back-calc gain, AW_BACKCALC only

Mode 0 — AW_LEGACY

Integrate only while |E| < EMin; hard-clamp SumE to ±SumEMax. Reacts to error size, never to real saturation. Blunt but safe.

Mode 1 — AW_CLAMP (correct clamping)

SumE_prev = SumE;
SumE += E;                              // tentative integrate
u_presat = Up + Ui + Ud;
U = clamp(u_presat, ±UMax);
if (U != u_presat &&                    // actually saturated?
    sign(u_presat) == sign(E))          // and pushing further in?
    SumE = SumE_prev;                   // undo — freeze integrator

No EMin gate. Integrator runs freely until the output truly saturates, then freezes only in the offending direction. No tuning knob.

Mode 2 — AW_BACKCALC (observer)

SumE += E;                              // always integrate
u_presat = Up + Ui + Ud;
U = clamp(u_presat, ±UMax);
SumE += Kt * (U - u_presat);            // bleed by the saturation error

U - u_presat is 0 when unsaturated, negative when clipped high, positive when clipped low — so the accumulator is pulled back toward feasibility, smoothly, in proportion to how much it was denied. Kt must be > 0 or this becomes pure always-integrate (worse than legacy).

Kt starting point A common heuristic is Kt ≈ 1/Ti = Ki/Kp (in this code's units, try Kt near Ki/Kp and tune). Larger Kt → faster unwind but noisier; smaller → gentler. Always sweep it in sim/ first.
Known limitation Saturation here is detected at the rate-PID's own UMax, which is a proxy. The real actuator limit is downstream at the motor mixer. Good enough to fix rate-loop windup; a mixer-referenced version is a later refinement.

How to enable (per loop)

// e.g. in MRAC_Init() or a bench-test init:
Ctrler.gyroxPID.aw_mode = AW_CLAMP;          // roll rate loop, correct clamping
Ctrler.gyroyPID.aw_mode = AW_BACKCALC;       // pitch rate loop, observer
Ctrler.gyroyPID.Kt      = 0.002f;            // required for back-calc

Remember: gyrox=roll, gyroy=pitch. Leave a loop at default to keep its legacy behaviour.
