Kalman Filter

The optimal way to combine an uncertain model with a noisy sensor — for linear systems with Gaussian noise. Everything reduces to one gain, K.

Symbols

SymbolNameAnswers
xstatewhat you want to know (can't measure directly)
zmeasurementwhat the sensor actually gives you
Astate transitionhow the state evolves one step on its own
B, uinput model, inputhow your commands push the state
Hobservation modelwhich mix of states the sensor sees
w ~ N(0, Q)process noisehow much you distrust the model per step
v ~ N(0, R)measurement noisehow much you distrust the sensor
Pestimate covariancehow uncertain the current estimate is
KKalman gainwhat fraction of the innovation to accept
x̂⁻, P⁻prior (superscript −)after PREDICT, before the measurement

Common trap: Q and R both describe noise, but Q belongs to the process equation and R to the measurement equation. Tuning = choosing the Q:R ratio.

1-D Gaussian fusion (the core idea)

fuse N(μ₁, σ₁²) with N(μ₂, σ₂²):

  K  = σ₁² / (σ₁² + σ₂²)          // the Kalman gain
  μ  = μ₁ + K (μ₂ − μ₁)             // move toward the measurement by fraction K
  σ² = (1 − K) σ₁²                 // ALWAYS smaller than both inputs
  • K → 0: trust the model.   K → 1: trust the measurement.   The noisier a source, the less it contributes.
  • Every measurement — even a bad one — shrinks uncertainty by the factor (1 − K).

The full recursion

model:        xₖ = A xₖ₋₁ + B uₖ₋₁ + w,   w ~ N(0, Q)
measurement:  zₖ = H xₖ + v,               v ~ N(0, R)   // R here — not Q!

PREDICT  (every tick):
  x̂⁻ = A x̂ + B u
  P⁻ = A P Aᵀ + Q                    // uncertainty GROWS

UPDATE  (when a measurement arrives):
  S  = H P⁻ Hᵀ + R                   // innovation covariance
  K  = P⁻ Hᵀ S⁻¹
  x̂  = x̂⁻ + K (z − H x̂⁻)
  P  = (I − K H) P⁻                  // uncertainty SHRINKS

Predict and update can run at different rates: predict at the model rate, update whenever a sensor sample lands. Multiple sensors = multiple update steps, each with its own H and R.

This firmware

  • No Kalman filter exists in the firmware. All estimators are fixed-gain predict/correct loops.
  • Attitude: Mahony complementary filter, imu_update.c, 1 kHz. Predict = gyro quaternion propagation; update = accel cross-product error × constant Kp/Ki. Equivalent to a steady-state (converged-K) Kalman filter, made stable on SO(3).
  • Position/velocity: SINS fixed-gain observer corrections (SINS.h in_est/in_obs/fix_ki).
  • Trade-off of fixed gain: no covariance CPU cost, but trust can't adapt (e.g. accel corrupted by maneuvers still gets full weight).

Extensions (one line each)

  • EKF — nonlinear f(x), h(x); linearize with Jacobians each tick. The workhorse of drone autopilots (PX4/ArduPilot).
  • UKF — propagate a handful of sigma points through the true nonlinearity instead of linearizing.
  • Particle filter — drop Gaussians entirely; represent belief as weighted samples.
