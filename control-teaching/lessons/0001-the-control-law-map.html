Lesson 01 · Foundation

The Control-Law Map

Before you fold in a single idea from the video series, you need one picture in your head: where the signal flows, and where a new idea would bolt on.

Your firmware doesn't have one controller. It has a cascade of nested PID loops, fastest on the inside, and an adaptive layer (MRAC) that rides on the fastest loop. Every technique from the series attaches at exactly one point in this chain. If you can name that point, you can add the technique safely. That is the whole game.

The chain, top to bottom

Read a setpoint entering at the top; each box turns it into the setpoint for the box below. The bottom box drives the motors. Runs in Compute_Motor(), StabilizerTask.c, at 200 Hz.

Position PID locxPID / locyPID
→wants a velocity
Velocity PID
→wants a lean angle
Angle PID roll / pitch / yaw
→wants an angular rate
Rate PID gyrox / gyroy / gyrozPID
→wants a torque
+ MRAC adaptive term u_ad
→corrects the torque
Motor Mixer
→4 motor PWMs
Rate loop — the inner loop, where torque is born (and where anti-windup matters most) MRAC — the adaptive layer that learns a correction on top of the rate PID
Naming trap In this firmware gyrox = roll rate and gyroy = pitch rate (StabilizerTask.c:619–620). Wire a change to the wrong one and you'll tune pitch while watching roll. Keep this taped to your monitor.

How MRAC rides the rate loop

MRAC does not replace the rate PID. It reads the rate PID's output as a nominal command, then adds a learned correction:

// mrac.c:501  — nominal torque comes straight from the rate PID
mrac_state.pitch.u_nom = current_state->gyroyPID.U / mrac_config_pitch.mrac_to_mixer;

// mrac.c:511  — learn+add the adaptive term u_ad  (this axis only if its flag is on)
if (mrac_flags.axis_enable_pitch)
    MRAC_UpdateAxis(MRAC_AXIS_PITCH, &mrac_state.pitch, &mrac_config_pitch, cross_pitch, r_pitch);
else
    mrac_state.pitch.u_ad = 0.0f;   // flag OFF → adaptive term is exactly zero → pure PID
Your win The flag pattern your mission needs already exists. mrac_flags.axis_enable_pitch (and _roll, _yaw) is a runtime switch: OFF ⇒ the adaptive term is forced to zero ⇒ the vehicle flies on the untouched baseline PID. Every improvement you add from the series should copy this shape: a flag whose OFF state reproduces today's behaviour bit-for-bit.
The rule for every future lesson When we add technique X, we will ask three questions: (1) Which box does it attach to? (2) What flag gates it, and does OFF equal today? (3) How do we test ON vs OFF in sim/ before flying? Anti-windup — the video-2 topic — attaches to the Rate PID box, and it already ships ON. We'll dissect it next.
