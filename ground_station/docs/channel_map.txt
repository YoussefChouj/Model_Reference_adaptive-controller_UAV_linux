VOFA+ JustFloat: map VOFA channel index (I0, I1, ...) to signal names.
Names match vofa_channel_name() in serial_bridge.py (dots -> underscores).

UDP: serial_bridge sends Frame A and Frame B on TWO different ports so each
VOFA connection has a fixed float count (JustFloat requirement).

  Connection 1 (fast / 100 Hz): bind VOFA to local UDP vofa_port_a (default 1347)
                               -> 8 floats + 5 status bytes as floats (I0..I12) + tail

  Connection 2 (slow / 20 Hz): bind VOFA to local UDP vofa_port_b (default 1348)
                               -> 4*(MAX_NUM_BASIS+2)+36 floats (e.g. 68 for N=6)
                               -> then 7 extra JustFloat channels from the 22-byte path tail (u8/float mix)

Telemetry from the vehicle/simulator still goes to simulate_udp_port (default 50007)
for serial_bridge --simulate; the bridge unpacks and forwards to vofa_port_a / vofa_port_b.
GS_PROTO_VERSION = 8 (ADR-0010: bench frame 0x04 payload grew 12 -> 20 B; serial_bridge accepts both).

JUSTFLOAT CHANNEL MAP - Frame B (20 Hz)  --  UDP vofa_port_b (default 1348)
-------------------------------------------------------------------------------
Frame B length depends on MAX_NUM_BASIS from the telemetry header.
Wire format: 16-bit little-endian payload length = (4 * (MAX_NUM_BASIS + 2) + 36) * 4 + TAIL
(float block + path tail before CRC). TAIL = 26 (proto v3, adds real_voltage/status.vbat) or
22 (proto v2). serial_bridge accepts both so plots work before/after reflash.
Same header for Frame A (payload length 38, last byte = GS_PROTO_VERSION).

Float block channel count: 4 * (MAX_NUM_BASIS + 2) + 36  (this part scales with N).
Path tail is fixed 26 bytes in v3 / 22 in v2 (not MAX_NUM_BASIS-dependent); serial_bridge unpacks it to 8
(v3) or 7 (v2) extra (name, value) pairs appended after all MRAC+PID floats.

The list below is for MAX_NUM_BASIS = 6 (68 float channels I0..I67, then I68..I74 from path tail).
If MAX_NUM_BASIS = N, MRAC block uses 4*(N+2) floats; PID block stays 36 floats. Indices I0..I(4*(N+2)+35) are the float block; path fields are always the last 7 VOFA channels.

-------------------------------------------------------------------------------
JUSTFLOAT CHANNEL MAP - Frame 0x04 (motor bench test, ~100 Hz, ADR-0009 + ADR-0010)
-------------------------------------------------------------------------------
Emitted while motor_test_active is high. Replaces Frame A / Frame B in that
mode (same exclusivity rule as the 0x03 SysID frame). The frame is NOT routed
through VOFA+ JustFloat (it has fixed-byte non-float fields); instead it travels
on the telemetry mirror UDP socket as a JSON `bench` dict in serial_bridge.py.

Dual-length backward compat (mirror of Frame B v2/v3 pattern):
  v7 = 12 B (pre-ADR-0010): <I B H f B>                (no RPM fields)
  v8 = 20 B (ADR-0010)     : <I B H f B 4H>             (+ 4 x u16 RPM little-endian)

Wire layout (v8, GS_PROTO_VERSION = 8):
  u32 sample_counter    increments per frame; detects dropped frames in the GS log.
  u8  motor_id          1..4 (echoes the firmware's selected bench motor).
  u16 commanded_ccr     commanded CCR [2000..4000], firmware-clamped.
  f32 real_voltage      pack voltage sampled fresh in the frame builder.
  u8  active            1 = bench-test live, 0 = tail frame after stop.
  u16 rpm0..3           four RPM channels (PA5/PB3/PB10/PB11), 0 when stopped/stale.
                        Channel index is the sensor socket, NOT the motor number;
                        on the bench only one sensor is plugged, the other three read 0.

Dashboard use:
  bench.rpm       = max(rpm0..rpm3)         (the live sensor's RPM)
  bench.rpm1..4   = the four channels verbatim
  bench.t_est_N   = k * (omega_measured)^2  appended to the bench CSV log row
